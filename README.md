# notereader

複数ディレクトリに散在する HTML / Markdown ファイル（Claude Code とのやり取りのまとめ等）を、ブラウザから横断検索・閲覧するローカルサーバー。

- 日本語全文検索（bleve の CJK bigram）＋ ASCII の語の前方一致・typo 許容
- 既定は更新日時順、スコア順にも切り替え可
- 選択したファイルをその場でプレビュー、`⌘+Enter` で新しいタブに開く（同じディレクトリの CSS・画像などの相対参照もそのまま解決）
- Markdown は HTML に変換して表示（コードは色付き、Mermaid は図として描画。オフラインで動く）
- それ以外のテキストファイル（`.go`・`.sh`・`.yaml` など）は、開くと色付きのコードとして表示。設定した拡張子は検索にも出る
- インデックスはディスクに保存され、起動時は変更のあったファイルだけを読み直す
- ファイルの追加・更新・削除を自動で検知して反映（画面も自動で追随）
- 単一バイナリ + YAML 設定。外部サービス不要
- `start` / `stop` / `status` でバックグラウンドに回せる。設定もコマンドで足し引きできる

## インストール

```bash
go install github.com/abetd/notereader/cmd/notereader@latest
```

clone して入れるなら `go install ./cmd/notereader`（または `make install`）。

## はじめに

```bash
notereader config init                  # ~/.config/notereader/config.yaml に雛形を書き出す（roots は空）
notereader config add notes ~/notes     # 見たいディレクトリをルートとして足す
notereader start                        # バックグラウンドで起動
```

`http://127.0.0.1:8787` を開く。

## コマンド

| コマンド | 動作 |
|----------|------|
| `notereader` | ヘルプを出す |
| `notereader serve` | 前面で起動する。`Ctrl-C` で停止。ログは標準エラーに出る |
| `notereader start` | バックグラウンドで起動し、応答するまで待ってから URL を出す。既に動いていれば何もしない |
| `notereader stop` | バックグラウンドのサーバーを止める（SIGTERM を送り、最大 10 秒待つ） |
| `notereader restart` | 止めてから起動する。止まっていれば起動だけ行う |
| `notereader status` | 動いているか・PID・URL・ファイル数を出す。終了コードは、動いていて応答があれば 0、止まっていれば 1、プロセスはいる（または何かが応答している）が正常に応答しなければ 2 |
| `notereader reindex` | 動いているサーバーで差分の再インデックスを行い、終わるまで待って件数を出す。監視（`watch: false`）を切っているときや、監視が拾わなかった変更をすぐ反映したいときに使う。止まっていれば終了コード 1（止まっている間の変更は次の起動時に取り込む）、正常に応答しなければ 2、同期が失敗すれば 1 |
| `notereader config init [--force]` | 設定ファイルの雛形（[config.example.yaml](./internal/config/config.example.yaml)）を書き出す。既にあれば `--force` が無い限り上書きしない |
| `notereader config show` | 設定ファイル・PID ファイル・ログの場所と、既定値を埋めた設定を出す。誤りがあれば終了コード 1 |
| `notereader config edit` | `$VISUAL` → `$EDITOR` → `vi` の順でエディタを開く。閉じたら検証し、バックグラウンドで動いていれば再起動する。ファイルが無ければ雛形を書いてから開く |
| `notereader config add <name> <dir>` | `path` 形式のルートを末尾に足す。ホーム配下のパスは `~/` 始まりで書き込む |
| `notereader config remove <name>` | ルートを丸ごと消す |

- どのコマンドも `--config` / `-c` で設定ファイルを指定できる（既定は `~/.config/notereader/config.yaml`。`XDG_CONFIG_HOME` があればその下）
- `config add` / `remove` は書き戻す前に検証し、通らなければファイルを書き換えない。コメントと並びは保つ。バックグラウンドで動いていれば再起動して反映する
- 再起動するのは `start` で起動したもの（PID ファイルがあるもの）だけ。`serve` で前面起動したものは、止めて起動し直す
- 変更前の設定が読めないとき（壊れた YAML を `config edit` で直したときなど）は、変更後の設定の `data_dir` で動いているものを探して再起動する
- `paths` 形式のルート（複数ディレクトリをまとめたもの）の中身を変えるときは `config edit` で手で書く
- 設定ファイルを手で書き換えたときは、`notereader restart` で反映する（設定ファイルは監視していない）

### バックグラウンド起動の仕組み

`start` は自分自身を `notereader serve` として端末から切り離して起動する。PID ファイルとログは `data_dir` 配下に置く。

| ファイル | 中身 |
|----------|------|
| `notereader.pid` | 動いているプロセスの PID |
| `notereader.log` | ログ。`start` のたびに前回分を `notereader.log.1` に回す（1 世代だけ残す） |

- 起動に失敗したら（ポートが使用中など）、ログの末尾を出して終了コード 1 で終わる。設定の誤りは子プロセスを起こす前に検証し、その場でエラーを出す
- PID ファイルが残っていてもそのプロセスがいなければ、古いものとして消してから起動する
- 同じアドレスで `serve` が前面で動いているときは、`start` は起動せずにエラーを出す
- `stop` は強制終了しない。10 秒待っても止まらなければ、その旨と `kill -9 <PID>` を出して終わる
- `serve` で前面起動したものは PID ファイルを作らないので、`stop` では止められない（`Ctrl-C` で止める）。`status` には「前面で動いています」と出る
- `stop` と `status` は設定のうち `listen` と `data_dir` だけを読む。監視対象のディレクトリが消えて設定の検証が通らなくなっていても止められる
- ログイン時の自動起動（launchd など）は用意していない

## 設定

`~/.config/notereader/config.yaml` に置く。例は [config.example.yaml](./internal/config/config.example.yaml)。

```yaml
roots:
  - name: notes          # URL とファイル ID に使う。一度決めたら変えない
    path: ~/notes
  - name: boards         # 複数のディレクトリを 1 つの名前にまとめる
    paths:
      - ~/projects/app/.scratch         # → app-scratch/...
      - ~/projects/dotfiles/.scratch    # → dotfiles-scratch/...
      - path: ~/projects/docs           # ラベルは明示もできる
        label: docs
exclude:
  - dist
```

| キー | 既定値 | 説明 |
|------|--------|------|
| `listen` | `127.0.0.1:8787` | 待ち受けアドレス。ループバック（`127.0.0.1`・`[::1]`・`localhost`）に限る |
| `data_dir` | macOS: `~/Library/Caches/notereader`、Linux: `~/.cache/notereader` | インデックス・PID ファイル・ログの保存先 |
| `watch` | `true` | ファイル監視の有無 |
| `reconcile_interval` | `5m` | 保険の定期照合の間隔。`"0"` で行わない。負の値はエラー |
| `roots[].name` | （必須） | 英数字・`_`・`-`。重複不可。URL のパスになるので `api`・`view`・`files`・`static` は使えない |
| `roots[].path` | `paths` と排他 | 再帰的に走査するディレクトリ |
| `roots[].paths` | `path` と排他 | 複数のディレクトリを 1 つの名前にまとめる。相対パスの先頭にディレクトリを表す名前が付くので、同じ相対パスのファイルがあっても衝突しない。名前はパスの末尾から自動で決まり、重なる場合は区別できるまで親を足す（`.scratch` が複数なら `app-scratch` / `dotfiles-scratch`）。`{path:, label:}` 形式で明示もできる。ラベル無しで 1 件だけ書いたときは名前を付けない（`path` と同じ）。後から 2 件目を足すと名前が付き、そのルートのファイル ID と URL がすべて変わる。同じディレクトリの重複（別のルートとの重複も含む）・入れ子のディレクトリ・ラベル重複はエラー |
| `exclude` | なし | 除外する名前（ディレクトリ名・ファイル名）・相対パスの glob。相対パスは各ディレクトリから数える（`paths` で付く名前は含めない）。`.git`・`node_modules`・`.next`・`.venv`・`.env` などは常に除外（一覧は `internal/config` の `DefaultExclude`）。`.scratch` は対象 |
| `code` | なし | コードとして索引に入れる拡張子（`.go`・`go` のどちらで書いてもよい。大文字小文字は区別しない）。拡張子だけを書く（`.d.ts` のような二重の拡張子はエラー。`Makefile` のようなファイル名は拡張子 `.makefile` として扱われ、そのファイルには一致しない）。`.html`・`.htm`・`.md`・`.markdown` はエラー。外した拡張子のファイルは、再起動したときの同期で索引から消える（索引の作り直しは要らない）。開いたときのコード表示はこの設定に関係なく効く（[コード表示](#コード表示)） |
| `archive` | `[archive]` | アーカイブとみなすディレクトリの名前・相対パスの glob。どの階層のディレクトリにも当てる（ファイル名には当てない）。相対パスはルートから数える（`paths` のルートでは `app-scratch/old` のように付いた名前から書く）。書くとその内容で既定を置き換え、`[]` で無効 |

走査ではシンボリックリンクを辿らない（`/files/...` での配信は、ルートの中を指すものなら辿る）。

`http://localhost:8787/{ルート名}`（例: `/notes`）を開くと、そのルートだけを対象にした画面になる。画面上部のセレクタで「すべて ⇄ 個別のルート」を切り替えられる（検索語・並び順・「アーカイブも含める」は保たれる）。

### アーカイブ

古いファイルを `archive/` などのディレクトリに移しておくと、検索画面の一覧には既定で出なくなる。`exclude` と違って索引には入ったままで、`/view/{id}`・`/files/...` で開ける。画面上部の「アーカイブも含める」にチェックを入れると一覧に出て、「アーカイブ」のバッジで見分けられる。

- アーカイブかどうかは検索のたびに相対パスで判定する（索引には持たない）。`archive` を変えたら再起動すれば反映され、索引の作り直しは要らない
- アーカイブに移すと相対パスが変わるので、ファイル ID も変わる（移す前の `/view/{id}` やブックマークは 404 になる）

## 画面の操作

左に検索結果、右に選択中のファイルのプレビューを並べた 2 ペイン構成。検索欄に入力したまま、キーボードだけで絞り込み・確認・表示までできる。

| キー | 動作 |
|------|------|
| `↓` / `Ctrl+N` | 次の結果を選択（プレビューが切り替わる） |
| `↑` / `Ctrl+P` | 前の結果を選択 |
| `⌘+Enter` / `Ctrl+Enter` | 選択中の結果を新しいタブで開く（入力直後でも最新の結果に対して動く） |
| `Esc` | 検索語をクリア（ヘルプが開いていれば閉じる） |
| `/` | 検索欄にフォーカス |

キー操作は画面右上の `?` にも出る（外をクリックするか `Esc` で閉じる）。

- 検索するたびに先頭の結果が選択される
- IME 変換中のキー（変換確定の `Enter` など）は無視する
- 一覧はクリックで選択する。開くのは `⌘+Enter` / `Ctrl+Enter` かプレビューの上の「新しいタブ」だけで、この画面のまま別のファイルに移ることはない（検索画面を残すため）
- 一覧には ルート名と種別（`HTML` / `MD`、コードは拡張子の大文字で `GO` など）のバッジ・アーカイブ内なら「アーカイブ」のバッジ・更新日時・タイトル・一致箇所のスニペット（2 行）を出す。ファイルパスはプレビューの見出しに出す
- 更新日時は 今日なら時刻（`13:51`）、昨日は `昨日`、10 日前までは `n 日前`、それより前は日付（`2026/9/19`）。ホバーで正確な日時が出る
- プレビューの読み込みは 150ms 待つので、キーを押しっぱなしで移動しても読み込みが走らない
- 幅 860px 以下ではプレビューを畳んで一覧だけにする
- 選択中のファイルは URL の `id` に入るので、リロードしても同じファイルを表示したまま（URL を共有しても同じ状態で開ける）
- 表示中のファイルが書き換えられると、プレビューだけを自動で読み込み直す。他のファイルが更新されても表示は切り替わらない
- 「アーカイブも含める」は既定でオフ。オンにすると URL に `archive=1` が入り、リロード・戻る・ルートの切り替えでも保たれる。ルートの選択肢の件数もチェックに合わせて数える。キー操作は無い（クリックか Tab で操作）
- 画面右上には、同期中は「同期中…」、検索・状態の取得・同期に失敗したときはその理由を出す。うまくいっているときは何も出さない

## Markdown

`.md` / `.markdown` も HTML と同じように検索・閲覧できる。

- 表示は goldmark で HTML に変換したもの。元のファイルは書き換えない
- コードブロックは chroma でサーバー側ハイライト（配色はライト / ダークで切り替わる）
- ` ```mermaid ` のブロックは図として描画する。Mermaid はバイナリに同梱しているのでオフラインでも動く（`web/static/vendor/`。更新手順はそこの README）
- 元の Markdown が見たいときは URL に `?raw=1` を付ける
- 検索のタイトルは frontmatter の `title` → 最初の見出し → ファイル名 の順で決まる
- 検索の本文には**コードブロックの中身も含める**（識別子やコマンドで引けるように）

## コード表示

HTML / Markdown 以外のテキストファイルは、ブラウザで開くと Markdown のコードブロックと同じ見た目（chroma のハイライト、行番号なし、長い行は横スクロール）で表示する。Markdown や HTML からのリンクで開いたときも同じ。

- 言語はファイル名（拡張子・`Makefile` などの名前）から決める。分からなければ色を付けない
- テキストかどうかは中身で判定する（先頭 8 KB に NUL を含まず、UTF-8 として読める）。テキストでなければ元のまま返す
- 1 MB を超えるファイルは色を付けずに表示する
- コード表示にするのは、ページとして開かれたとき（新しいタブ・プレビュー。リクエストの `Sec-Fetch-Dest` が `document` / `iframe`）だけ。HTML から読み込まれる CSS・JS・`fetch` や、curl などには元のまま返す
- SVG など画像として扱われるもの（Content-Type が `image/*`）は変換しない
- 元のまま見たいときは URL に `?raw=1` を付ける（Content-Type によってはダウンロードになる）
- 検索の一覧に出すのは、設定の `code` に書いた拡張子のファイルだけ（既定は空）。タイトルは `path` / `paths` のディレクトリから数えたパス（`PROJ-123/scripts/fix.sql` のように拡張子も含む。`paths` で付く名前は含めない）、本文はファイル全体。コード表示のページのタイトルも同じパス

## 検索の挙動

- 空白区切りの語はすべて含むもの（AND）
- 日本語を含む語は部分文字列として一致（bigram のフレーズ一致）。1 文字だけの語はヒットしない
- ASCII だけの語（`v2`・`b.html` なども含む）は前方一致。英数字だけで 4 文字以上なら、編集距離 1 までの typo も許容
- タイトル > ファイル名 > 本文 の順に高く評価
- 並び順の既定は更新日時の新しい順。スコア順は `sort=score`（検索語が無いときはスコアが付かないので常に更新日時順）

## API

| メソッド・パス | 説明 |
|----------------|------|
| `GET /` | 検索画面（全ルート） |
| `GET /{ルート名}` | そのルートだけの検索画面 |
| 画面の URL | `?q=検索語&sort=score&archive=1&id=ファイルID`（`sort` は既定 `mtime` のとき、`archive` は含めないとき省略） |
| `GET /api/search?q=..&sort=score\|mtime&limit=..&root=..&archive=1` | 検索（JSON）。`sort` は既定 `mtime`、`limit` は既定 20・最大 100。`root` を付けるとそのルートだけに絞る（不明な名前は 400）。アーカイブ内のファイルは既定で除き、`archive=1` で含める（結果の `archived` で見分ける） |
| `GET /view/{id}` | `/files/{root}/{相対パス}` へリダイレクト |
| `GET /files/{root}/{相対パス}` | ルート配下のファイルを配信（除外対象のパス・ルート外は 404）。`.md` は HTML に変換して返す。それ以外のテキストファイルは、`Sec-Fetch-Dest` が `document` / `iframe` のときコード表示の HTML を返す。どちらも `?raw=1` で元のまま。HTML / Markdown・画像以外の応答には、コード表示にしたかどうかに関わらず常に `Vary: Sec-Fetch-Dest` を付ける |
| `POST /api/reindex` | 差分再インデックスを開始（実行中なら 409）。`notereader reindex` が使う |
| `GET /api/status` | PID・件数・ルート（ごとの件数つき）・直近の同期結果。件数はアーカイブを含み、そのうちアーカイブ内の数を `archived` に出す |

`Host` ヘッダが `localhost` / ループバック IP 以外のリクエストは 403 を返す（DNS リバインディング対策）。停止用の API は無い（ブラウザで開いた別のサイトから止められないようにするため。止めるのは `notereader stop`）。

## 仕組み

- ファイル ID は `sha256(ルート名 + "\0" + 相対パス)` の先頭 16 桁。ルートディレクトリを移動しても `name` が同じなら ID は変わらない
- 変更検知は更新日時（ns）+ サイズで行い、変わったファイルだけ再抽出する。消えたファイルはインデックスから削除する（読めなかったルート・ディレクトリの分は残す）
- `data_dir/meta.json` にスキーマバージョンを記録し、不一致ならインデックスを作り直す

## ファイル監視

fsnotify で監視対象ディレクトリを見張り、変化があればインデックスを同期する。画面は 3 秒ごとにインデックスの更新を見て、変わっていれば検索結果を取り直す（選択中の項目は維持される）。

- イベントの種別は解釈せず「どこかが変わった」という合図としてだけ使い、変化があったら更新日時+サイズで全体を照合し直す（rename・tmp からの差し替え・サブディレクトリ追加など、イベントの出方の違いに影響されないため）
- イベントが止んでから 0.5 秒待ってまとめて同期する（書き込みが続く場合も最大 3 秒で同期する）
- 起動後に作られたディレクトリも監視に加える
- 取りこぼしの保険として、既定で 5 分ごとにも照合する（`reconcile_interval`。`"0"` で無効）
- `watch: false` にすると監視せず、起動時と `notereader reindex` でのみ更新する

macOS では、監視対象のファイル 1 つにつきファイルディスクリプタを 1 つ使う（kqueue）。数千ファイル規模で常駐させるなら、開けるファイル数の上限（`ulimit -n`）に注意する。`start` で起動した子プロセスは、`start` を実行したシェルの上限を引き継ぐ。

## 開発

```bash
make test    # go test ./...
make lint    # golangci-lint run（v2 が要る。設定は .golangci.yml）
make fmt     # golangci-lint fmt（gofmt・goimports）
make build   # bin/notereader
make run ARGS="serve -c ./config.yaml"
```

`cmd/notereader` のテストはバイナリをビルドして、`start` / `stop` / `config` などを実際のプロセスとして動かす。

`web/` を触ったときは、ブラウザで次を確認する（自動テストは無い）。

1. `↓↑` / `Ctrl+N・P` で選択が動き、プレビューが切り替わる
2. `⌘+Enter` と「新しいタブ」で新しいタブに開き、`Enter` だけでは何も起きない・`Esc` でクリア・`/` で検索欄へ・`?` のヘルプが外のクリックで閉じる
3. 選択したままリロードして、同じファイルが表示される（URL の `id`）
4. 表示中のファイルを書き換えると、数秒でプレビューが更新される
5. ファイルを足す・消すと、一覧が自動で追従する
6. Markdown のコードハイライトと Mermaid の図が出る
7. `code` に書いた拡張子のファイルが一覧に出て、バッジが拡張子の大文字（`GO` など）になる。プレビューと新しいタブでコードが色付きで出る。HTML から読み込む CSS・JS は壊れない
8. ライト / ダークの両方で崩れていない
9. サーバーを止めると右上に「サーバーに接続できません」が出て、起動し直すと消える

```
cmd/notereader/     エントリポイントとサブコマンド（kong）
internal/config/    YAML 読み込み・検証・除外判定、config add / remove の書き戻し、config init の雛形（config.example.yaml）
internal/daemon/    バックグラウンド起動・停止（PID ファイル・ログ）、動いているサーバーへの問い合わせ（status・reindex）
internal/extract/   形式ごとの抽出器（HTML・Markdown・コード）
internal/highlight/ chroma でのコードハイライト（Markdown のコードブロックとコード表示で共用）
internal/indexer/   bleve マッピング・差分同期
internal/markdown/  Markdown → HTML 変換
internal/search/    クエリ組み立て
internal/server/    HTTP ハンドラ
internal/watcher/   ファイル監視
web/                テンプレート・静的ファイル（バイナリに埋め込み）
```
